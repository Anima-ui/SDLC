# Разбор исходного кода

## `Main`

`Main.main` — точка входа. Вызов `SwingUtilities.invokeLater` помещает создание интерфейса в Event Dispatch Thread (EDT), специальный поток Swing. Компоненты Swing следует создавать и изменять в этом потоке, иначе возможны гонки данных и нестабильное отображение.

`UIManager.setLookAndFeel` включает системное оформление Windows. Если оно недоступно, исключение перехватывается и Swing использует стандартную тему. После этого создаются единственные экземпляры модели и главного окна, а контроллер связывает их.

## Классы модели

### `HeroData`

`record` хранит пять входных значений. Java автоматически создаёт конструктор и методы доступа `heightCm()`, `weightKg()`, `age()`, `pullUps()` и `sleepHours()`.

Объект неизменяем: после создания его значения нельзя заменить. Это удобно для передачи одного согласованного набора параметров между контроллером и моделью.

### `HeroLevel`

`enum` задаёт закрытый набор возможных результатов. Благодаря этому уровень не может случайно принять произвольную строку. У каждой константы есть русское название, возвращаемое методом `title()`.

### `HeroResult`

Содержит рассчитанные уровень, сумму баллов и ИМТ. Входные данные и результат разделены, поэтому понятнее, какие значения ввёл пользователь, а какие вычислила программа.

### `ValidationException`

Собственное проверяемое исключение сообщает контроллеру о неверных данных. Модель формирует конкретный текст ошибки, а представление только показывает его.

### `SuperHeroModel`

Поля `lastData` и `result` — текущее состояние приложения. Сначала они равны `null`, потому что расчёта ещё не было.

Метод `calculate` выполняет операцию в строгом порядке:

1. `validate(data)` проверяет входные значения.
2. При успехе модель запоминает данные.
3. `evaluate(data)` создаёт результат.
4. `firePropertyChange` сообщает об изменении.

Если проверка вызывает исключение, присваивания не выполняются. Поэтому некорректный ввод не уничтожает предыдущие корректные данные.

Методы `bodyMassScore`, `ageScore` и `sleepScore` закрыты модификатором `private`, поскольку являются внутренними деталями алгоритма. Публичный интерфейс модели состоит из расчёта, чтения состояния и подписки на события.

При расчёте баллов за подтягивания сначала выполняется приведение к `long`. Оно предотвращает переполнение при умножении очень большого допустимого значения типа `int` на четыре.

## Контроллер

Конструктор `SuperHeroController` сохраняет ссылки на модель и главное окно, назначает обработчик кнопки и подключает окно как наблюдателя модели.

`openInputDialog` создаёт новый модальный диалог. В него передаётся `model.getLastData()`: при первом открытии это `null`, а при следующих — последний корректный набор значений.

`calculate` получает строки из формы и преобразует их в `HeroData`. Вспомогательные методы разделены по типам:

- `parseDouble` обрабатывает рост, вес и сон; он принимает и точку, и запятую;
- `parseInteger` обрабатывает возраст и подтягивания как целые числа.

Преобразование текста относится к контроллеру, потому что модель принимает уже типизированные данные. Проверка предметных правил остаётся в модели. Если возникает `ValidationException`, контроллер просит диалог показать ошибку. Диалог остаётся открытым, чтобы пользователь исправил значение.

## Главное представление `MainFrame`

Класс наследуется от `JFrame`. Он содержит заголовок, уровень, баллы, ИМТ, последние значения и кнопку открытия формы.

Интерфейс строится из вложенных панелей:

- `BorderLayout` делит окно на верхнюю, центральную и нижнюю области;
- `GridLayout` располагает строки результата равномерной сеткой;
- `BorderFactory` создаёт отступы и рамку.

Метод `setInputAction` не знает, что именно произойдёт после нажатия. Контроллер передаёт ему действие типа `Runnable`. Метод `observe` подписывает окно на модель, а `showState` отображает полученное состояние.

## Представление ввода `InputDialog`

Класс наследуется от `JDialog`. Параметр `true` в конструкторе делает окно модальным: пока оно открыто, нельзя взаимодействовать с главным окном.

Пять объектов `JTextField` хранят введённый текст. `getRootPane().setDefaultButton(calculateButton)` позволяет запустить расчёт клавишей Enter. Кнопка «Отмена» закрывает диалог без изменения модели.

Метод `fill` восстанавливает последние значения. Методы `heightText`, `weightText` и остальные отдают контроллеру текст, но само представление ничего не вычисляет.

## Использованные принципы ООП

- **Инкапсуляция:** поля закрыты, доступ выполняется через методы; внутренняя формула модели скрыта.
- **Наследование:** `MainFrame` наследует `JFrame`, а `InputDialog` — `JDialog`.
- **Полиморфизм:** слушатели передаются как реализации функциональных интерфейсов `Runnable`, `ActionListener` и `PropertyChangeListener`.
- **Абстракция:** `HeroData` описывает вход, `HeroResult` — выход, `HeroLevel` — ограниченный набор уровней.

Лямбда `event -> action.run()` является компактной реализацией интерфейса слушателя события. Ссылка на метод `this::openInputDialog` означает: при выполнении действия вызвать метод `openInputDialog` текущего контроллера.
