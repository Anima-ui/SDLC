# Архитектура MVC

MVC расшифровывается как Model–View–Controller: модель, представление и контроллер. Разделение нужно, чтобы расчёт, интерфейс и обработка действий пользователя не находились в одном большом классе.

| Часть | Классы проекта | Ответственность |
|---|---|---|
| Model | `SuperHeroModel`, `HeroData`, `HeroResult`, `HeroLevel`, `ValidationException` | Данные, проверка допустимости, расчёт и уведомление об изменении |
| View | `MainFrame`, `InputDialog` | Отображение состояния, поля ввода, кнопки и сообщения об ошибках |
| Controller | `SuperHeroController` | Реакция на кнопки, чтение текста, преобразование в числа и вызов модели |

`Main` является точкой сборки приложения: он создаёт модель, представление и контроллер и связывает их. Он не содержит предметного расчёта.

## Как проходит один расчёт

1. Пользователь нажимает «Ввести данные» в `MainFrame`.
2. Контроллер открывает модальный `InputDialog` и передаёт ему последние данные модели.
3. Пользователь вводит значения и нажимает «Рассчитать».
4. Контроллер получает строки из полей, заменяет десятичную запятую точкой и преобразует строки в числа.
5. Контроллер создаёт неизменяемый объект `HeroData` и вызывает `model.calculate(data)`.
6. Модель проверяет значения, вычисляет ИМТ, баллы и уровень, затем сохраняет `HeroData` и `HeroResult`.
7. Модель вызывает `firePropertyChange` и уведомляет подписчиков.
8. `MainFrame`, подписанный методом `observe`, получает событие, читает новое состояние модели и обновляет надписи.
9. Если ошибок не было, контроллер закрывает окно ввода.

## Почему модель активная

Ключевой признак находится в `SuperHeroModel`:

```java
changes.firePropertyChange(STATE_PROPERTY, oldData, data);
```

Модель не ждёт, пока контроллер заберёт результат и прикажет главному окну обновиться. После изменения модель сама публикует событие. `MainFrame` заранее подписывается на такие события:

```java
model.addPropertyChangeListener(event -> {
    if (SuperHeroModel.STATE_PROPERTY.equals(event.getPropertyName())) {
        showState(model.getLastData(), model.getResult());
    }
});
```

Это сочетание активной модели и паттерна Observer («Наблюдатель»):

- `SuperHeroModel` — наблюдаемый объект;
- `PropertyChangeListener` — наблюдатель;
- `PropertyChangeSupport` хранит слушателей и рассылает события;
- `STATE_PROPERTY` позволяет отличить изменение состояния от других возможных событий.

Модель не знает о конкретных компонентах Swing и не вызывает методы `JLabel` или `JFrame`. Она работает с абстрактными слушателями. Поэтому расчётный код не зависит от интерфейса.

## Чем пассивная модель отличалась бы от этой реализации

При пассивной модели конец метода контроллера выглядел бы примерно так:

```java
model.calculate(data);
view.showState(model.getLastData(), model.getResult());
```

То есть контроллер вручную обновлял бы окно. В текущем проекте второй строки нет: обновление запускает событие самой модели. Это главный аргумент на защите.

## Направления зависимостей

- Модель использует только стандартные классы `java.beans` и не импортирует Swing.
- Представление знает типы данных модели, потому что отображает их и подписывается на состояние.
- Контроллер знает модель и оба представления, поскольку связывает пользовательские действия с операциями модели.
- `Main` создаёт все главные объекты и передаёт зависимости через конструктор.

Такое разделение позволяет менять формулу в модели, почти не затрагивая окна, или заменить Swing-интерфейс, сохранив расчёт.
