# Описания актёров и прецедентов

Документ сопровождает [диаграмму вариантов использования](../uml/use-case.puml). Для каждого прецедента приведены пояснение, предусловия, основной и альтернативные потоки и постусловия.

## Актёры

| Актёр | Описание роли |
|---|---|
| Гость | Неавторизованный посетитель. Создаёт учётную запись или входит в существующую |
| Пользователь | Авторизованный владелец приватной коллекции. Ищет фильмы, ведёт записи, импортирует и экспортирует данные, получает рекомендации |
| Администратор | Авторизованный пользователь с ролью `ADMIN`. Исправляет локальный каталог и запускает его синхронизацию |
| TMDB | Внешняя система, предоставляющая общие метаданные фильмов. Личные оценки и заметки ей не передаются |

## UC-01. Регистрация и вход

**Пояснение.** Гость создаёт учётную запись или открывает защищённые разделы существующего аккаунта.

**Предусловия.** Гость не имеет действующего сеанса.

**Основной поток.** 1. Гость выбирает регистрацию или вход. 2. Вводит email и пароль. 3. Система проверяет данные. 4. При регистрации система сохраняет уникальный email и хэш пароля; при входе сверяет пароль. 5. Система создаёт ограниченный по времени сеанс.

**Альтернативные потоки.** Неверный формат или занятый email отклоняется с пояснением. Неверные данные входа дают нейтральное сообщение. После пяти неудачных входов источник временно ограничивается.

**Постусловия.** При успехе пользователь авторизован; при отказе аккаунт и сеанс не создаются.

## UC-02. Поиск и просмотр фильма

**Пояснение.** Пользователь находит фильм по части названия и открывает его карточку.

**Предусловия.** Пользователь авторизован.

**Основной поток.** 1. Пользователь вводит строку поиска и при необходимости выбирает жанр и год. 2. Система выполняет регистронезависимый поиск. 3. Пользователь открывает найденную карточку. 4. Система показывает название, год, жанры, описание и личный статус.

**Альтернативные потоки.** При пустой выдаче система предлагает сбросить фильтры. При недоступности TMDB используются локальные карточки и показывается сообщение об ограниченном режиме. Неактивные карточки в новом поиске не отображаются.

**Постусловия.** Карточка показана либо пользователь получил объяснение отсутствия результата; коллекция не изменена.

## UC-03. Управление личной коллекцией

**Пояснение.** Пользователь добавляет фильм, меняет его статус и личные поля либо удаляет запись.

**Предусловия.** Пользователь авторизован; выбран фильм или собственная личная запись.

**Основной поток.** 1. Пользователь выбирает статус «Хочу посмотреть», «Просмотрен» или «Брошен». 2. Для просмотренного фильма при желании вводит дату, оценку 1–10 и заметку. 3. Система проверяет владельца и значения. 4. Система транзакционно создаёт или изменяет единственную запись пары «пользователь–фильм». 5. Обновлённая запись отображается в коллекции.

**Альтернативные потоки.** Неверное поле подсвечивается, остальные значения формы сохраняются. Повторное добавление не создаёт дубль. Для удаления система запрашивает подтверждение; отмена оставляет запись без изменений. Сбой сохранения приводит к откату.

**Постусловия.** При успехе коллекция содержит одну актуальную запись; при ошибке сохраняется прежнее состояние.

## UC-04. Получение рекомендаций

**Пояснение.** Пользователь получает до десяти активных непросмотренных фильмов с объяснениями.

**Предусловия.** Пользователь авторизован; локальный каталог доступен.

**Основной поток.** 1. Пользователь открывает рекомендации. 2. Система читает его статусы и оценки. 3. Исключает просмотренные, брошенные и неактивные фильмы. 4. При наличии минимум трёх оценок вычисляет предпочтения жанров и ранжирует кандидатов. 5. Показывает до десяти уникальных карточек с причинами.

**Альтернативные потоки.** При менее чем трёх оценках показывается общий набор и объяснение холодного старта. При отсутствии кандидатов показывается пустое состояние. Ошибка расчёта приводит к общему допустимому списку либо понятной ошибке.

**Постусловия.** Подборка показана; личная коллекция автоматически не изменяется.

## UC-05. Импорт коллекции из CSV

**Пояснение.** Пользователь переносит существующий список фильмов после обязательного предварительного просмотра.

**Предусловия.** Пользователь авторизован; подготовлен CSV UTF-8 требуемого формата; локальный каталог доступен.

**Основной поток.** 1. Пользователь выбирает файл. 2. Выполняется UC-06 «Предварительный просмотр импорта». 3. Пользователь подтверждает импорт. 4. Система повторно проверяет тот же файл и текущее состояние коллекции. 5. Допустимые новые записи сохраняются одной транзакцией. 6. Система показывает добавленные и пропущенные строки.

**Альтернативные потоки.** Пользователь отменяет операцию после просмотра — данные не меняются. Ошибочные, ненайденные, неоднозначные и повторные строки пропускаются с причиной. При техническом сбое транзакция полностью откатывается.

**Постусловия.** Добавлены только допустимые новые записи; существующие записи не перезаписаны и дубли не созданы.

## UC-06. Предварительный просмотр импорта

**Пояснение.** Система проверяет CSV до сохранения и показывает результат по строкам.

**Предусловия.** UC-05 запущен; пользователь выбрал файл.

**Основной поток.** 1. Система проверяет кодировку, заголовки и значения. 2. Сопоставляет строки с локальными фильмами по названию без учёта регистра и указанному году. 3. Выделяет новые записи, существующие записи и ошибки. 4. Возвращает результат пользователю без записи в БД.

**Альтернативные потоки.** При неверном формате всего файла система сообщает ошибку и не предлагает подтверждение. Неоднозначные и ненайденные фильмы отмечаются отдельно.

**Постусловия.** Коллекция не изменена; пользователь видит данные, необходимые для решения о подтверждении.

## UC-07. Экспорт коллекции в CSV

**Пояснение.** Пользователь получает переносимую копию своих личных записей.

**Предусловия.** Пользователь авторизован.

**Основной поток.** 1. Пользователь выбирает экспорт. 2. Система читает только его коллекцию. 3. Формирует CSV UTF-8 с заголовками, названием, годом, статусом, датой, оценкой и заметкой. 4. Браузер скачивает файл.

**Альтернативные потоки.** Для пустой коллекции формируется файл только с заголовками. При ошибке чтения файл успеха не возвращается.

**Постусловия.** Пользователь получил файл только со своими данными; БД не изменена.

## UC-08. Управление профилем

**Пояснение.** Пользователь изменяет отображаемое имя либо удаляет свою учётную запись.

**Предусловия.** Пользователь авторизован и открыл профиль.

**Основной поток.** 1. Система показывает разрешённые поля профиля. 2. Пользователь изменяет имя. 3. Система проверяет и сохраняет значение.

**Альтернативные потоки.** При неверном имени показывается ошибка без очистки формы. При удалении аккаунта система запрашивает повторное подтверждение и после него транзакционно удаляет аккаунт, личные записи и сеансы. Отмена не меняет данные.

**Постусловия.** Имя обновлено либо подтверждённый аккаунт и связанные личные данные удалены.

## UC-09. Управление локальным каталогом

**Пояснение.** Администратор создаёт, исправляет или деактивирует общую карточку фильма.

**Предусловия.** Действующий сеанс с ролью `ADMIN`.

**Основной поток.** 1. Администратор выбирает карточку или создаёт новую. 2. Вводит общие метаданные. 3. Система проверяет роль и поля. 4. Сохраняет карточку. 5. При деактивации скрывает её из нового поиска и рекомендаций.

**Альтернативные потоки.** Неверные данные отклоняются. Обычный пользователь получает отказ. Деактивация не удаляет существующие личные записи.

**Постусловия.** Локальная карточка создана, изменена или деактивирована; пользовательские оценки и заметки не изменены.

## UC-10. Синхронизация каталога с TMDB

**Пояснение.** Администратор запускает обновление общих метаданных из внешнего источника и просматривает результат.

**Предусловия.** Действующий сеанс с ролью `ADMIN`; настроен серверный токен TMDB.

**Основной поток.** 1. Администратор запускает синхронизацию. 2. Система фиксирует время начала. 3. Запрашивает данные у TMDB. 4. Нормализует и сохраняет карточки. 5. Фиксирует окончание, статус и количество обновлений. 6. Показывает результат администратору.

**Альтернативные потоки.** При тайм-ауте или ошибке TMDB система сохраняет безопасное описание ошибки, а локальный каталог остаётся доступен. Пользователь без роли `ADMIN` получает отказ.

**Постусловия.** Результат синхронизации записан; успешные обновления доступны локально, личные данные в TMDB не отправлены.
