# Дополнительные спецификации проекта «КиноНавигатор»

Документ фиксирует нефункциональные требования и ограничения из SRS 0.3, которые действуют для моделируемых UML-сценариев.

## 1. Производительность

- p95 открытия коллекции — не более 2 секунд при 100 параллельных пользователях, 10 000 фильмов и 1 000 записей на пользователя (`REQ-PERF-001`).
- p95 локального поиска — не более 1,5 секунды для запроса длиной не менее двух символов (`REQ-PERF-002`).
- Расчёт десяти рекомендаций — не более 3 секунд при коллекции до 1 000 записей (`REQ-PERF-003`).
- Один списочный ответ содержит не более 50 карточек; большие результаты разбиваются на страницы (`REQ-PERF-004`).

## 2. Безопасность

- Пароли хранятся только в виде стойкого адаптивного хэша с уникальной солью (`REQ-SEC-001`).
- Каждая защищённая операция проверяет аутентификацию и владельца личной записи на сервере (`REQ-SEC-002`).
- Production-cookie использует `HttpOnly`, `Secure` и допустимую политику `SameSite`; трафик вне локальной среды передаётся по HTTPS (`REQ-SEC-003`, `REQ-INT-007`).
- Пользовательский ввод проверяется, вывод экранируется; токены и пароли не попадают в репозиторий и журналы (`REQ-SEC-004`, `REQ-SEC-005`).
- После пяти неудачных входов источник временно ограничивается; административные операции требуют роли `ADMIN` (`REQ-SEC-006`, `REQ-SEC-007`).

## 3. Надёжность и целостность данных

- Изменение личной записи выполняется атомарно: после сбоя остаётся прежняя либо полностью новая версия (`REQ-REL-001`).
- Отказ TMDB не блокирует чтение локального каталога и личной коллекции (`REQ-REL-002`).
- Для пары «пользователь–фильм» существует не более одной личной записи; повторный запрос не создаёт дубль (`REQ-REL-004`, `BR-01`).
- Предварительный просмотр CSV не меняет данные. Подтверждение повторно проверяет файл и сохраняет допустимые новые записи одной транзакцией (`REQ-FUNC-032`).
- Существующие записи при импорте не перезаписываются; ненайденные и неоднозначные фильмы пропускаются с объяснением (`REQ-FUNC-032`).

## 4. Доступность и удобство использования

- Основные сценарии выполняются с клавиатуры, видимый фокус следует логическому порядку (`REQ-INT-006`, `REQ-AVAIL-002`).
- Ошибка формы не очищает остальные введённые значения (`REQ-INT-003`).
- Загрузка, пустой результат, ошибка и успешное сохранение имеют различимые текстовые состояния (`REQ-INT-004`).
- Удаление личной записи и аккаунта требует подтверждения (`REQ-INT-005`).
- Ошибка не обозначается только цветом; изображения фильмов имеют альтернативный текст (`REQ-AVAIL-004`, `REQ-AVAIL-005`).

## 5. Совместимость и наблюдаемость

- API использует JSON, даты ISO 8601 и стандартные HTTP-коды; ошибки имеют единый объект с кодом и сообщением (`REQ-INT-007`, `REQ-INT-008`, `REQ-COMP-002`, `REQ-COMP-003`).
- CSV кодируется в UTF-8 и содержит строку заголовков (`REQ-COMP-001`).
- Каждый серверный запрос имеет идентификатор корреляции в ответе и журнале (`REQ-OBS-001`).
- Журналы не содержат пароли, токены и полный текст личных заметок (`REQ-OBS-003`).
